# Пользовательские пути Колоды

Документ описывает, что человек делает в приложении, какой результат ждёт и где это уже
проверено. Каждый путь получает ID. По этим ID валидируем работу: проверка называется
своим путём, а пробел виден сразу.

Платформы: **Т** телефон (ширина до 640 px), **Д** ПК, **Т/Д** оба.

Покрытие:
- `unit: имя` тест в `test_app.py`, без браузера;
- `браузер` проверено в браузере на стенде: скрипты лежат вне репозитория, их описание
  в разделе «Валидация»;
- `нет` автоматически не проверено.

## 0. Кто ходит по приложению

- **Гость.** Видит только экран входа. Каталога и ленты для него нет.
- **Новый читатель.** Только что зарегистрировался, подписок нет.
- **Постоянный читатель.** 20 60 каналов, лента с прочитанным и непрочитанным, несколько коллекций.
- **Читатель с Telegram.** Подключил Telegram и видит свои приватные каналы.
- **Два устройства.** Телефон и ПК на одном профиле.

## Открытые вопросы

1. **Счётчик и фильтр «Непрочитанные» считают только 14 дней (F4, F5).** Обычная лента
   показывает и старые непрочитанные. Либо счётчик тоже считает всё, либо лента показывает
   только 14 дней. Решает продукт.
2. **Быстрое «В коллекцию» из строки канала (C18).** Сейчас путь длиннее, чем мог бы быть:
   список, «Новая», галочка.
3. **Экспорт и импорт не включают коллекции (D1).** Перенос на другое устройство потеряет группы.
4. **Импорт списка каналов не покрыт тестами (D2).**

## Валидация

Каждый путь проверяем по его ID. Для каждого прогона фиксируем фикстуру (стенд с тремя
подписками и одной коллекцией), шаги, ожидание и результат. Пробел остаётся пробелом, пока
путь не проверен. Перед тем как доверять зелёному результату, проверку ломаем намеренно
(контрольная копия без нужного кода) и смотрим, что она падает.

Состояние проверок на сейчас:
- unit-тесты в `test_app.py` покрывают серверную часть большинства путей;
- браузерные проверки (collections, read, swipe, placeholder, edge, pull, gutters) лежат
  вне репозитория и покрывают часть путей из разделов 2, 3, 9, 10;
- пути экранов, регистрации, сброса пароля и импорта без проверки.

Следующий шаг: единый прогон путей на стенде, описанный в README, с одним отчётом по ID.
