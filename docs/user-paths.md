# Пользовательские пути Колоды

Документ описывает, что человек делает в приложении, какой результат ждёт и где это уже
проверено. Каждый путь получает ID. По этим ID валидируем работу: проверка называется
своим путём, а пробел виден сразу.

Платформы: **Т** телефон (ширина до 640 px), **Д** ПК, **Т/Д** оба.

Покрытие:
- `unit: имя` тест в `test_app.py`, без браузера;
- `браузер`: `ui_paths_check.py` проверяет путь в браузере на стенде, см. раздел «Валидация»;
- `нет` автоматически не проверено.

## 0. Кто ходит по приложению

- **Гость.** Видит только экран входа. Каталога и ленты для него нет.
- **Новый читатель.** Только что зарегистрировался, подписок нет.
- **Постоянный читатель.** 20 60 каналов, лента с прочитанным и непрочитанным, несколько коллекций.
- **Читатель с Telegram.** Подключил Telegram и видит свои приватные каналы.
- **Два устройства.** Телефон и ПК на одном профиле.

## Валидация

Проверки по ID лежат в `ui_paths_check.py`, описание в README. Каждая проверка создаёт свой
профиль через API, так что порядок не важен. Результат: PASS, FAIL или SKIP с причиной.
SKIP означает, что путь на этом стенде нечем проверить (нет постов, нет альбома, другое
устройство), а не что он прошёл.

Последний полный прогон на стенде без почты: 36 проверок, 35 PASS, 0 FAIL, 1 SKIP (F17: на первых
страницах не нашлось протухших кадров; при другом составе канала проходит). F4 потом переписали
на проверку обновления; прогон F2, F3, F4, X3 на стенде: PASS.

Что ещё не проверено в браузере (и почему):
- A5 to A8 почта: нужен SMTP или перехват писем;
- A9, A10: истечение сессии и два устройства;
- F1, F5, F6, F7 (поле поиска), F9, F10, F11, F13, F14, F18, F19: нужны отдельные сценарии;
- C13 лимиты в браузере (проверены сервером);
- C14, C15, C16: частично внутри C19; другой профиль через браузер;
- K1, K2, K4 to K9 каталог: сортировки, карточки, лимит;
- P4, P5: история канала и возврат из канала;
- D2, D3, D4, D5, D6: импорт файла, история, Telegram через QR;
- E1, E2, E4, X1: сеть, капча t.me, конфликт двух устройств, экранный диктор;
- N1 to N6 навигация: пройдены вручную в браузере на 420×900 и 1280×860, в
  `ui_paths_check.py` ещё не перенесены.

Перед тем как доверять зелёному результату, проверку ломают намеренно. Unit: повторный токен
сброса пароля падает без удаления токена. Браузер: копия, где лента игнорирует коллекции,
падает в C2 и C5; копия со старой отметкой, которая
отмечала посты, вставленные обновлением, падает в F4 (три непросмотренных поста отмечены), новая проходит.
