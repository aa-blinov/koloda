# Лента публичных Telegram-каналов

Веб-сервис: создай профиль с паролем, выбери публичные каналы и читай их публикации в личной ленте.
У каждого профиля отдельные подписки и отметки прочитанного. Для ленты не нужен аккаунт Telegram.

```bash
git clone https://github.com/aa-blinov/koloda.git && cd koloda
cp .env.example .env   # укажи данные SMTP-почты в .env
docker compose up -d
```

Открой **http://127.0.0.1:8090**, создай профиль, затем в **Каталоге** посмотри
публикации каналов и добавь подходящие — они появятся в ленте. На телефоне в той же сети открой `http://<ip-компа>:8090`.

## Как это работает

Посты берутся из публичной превью-страницы `t.me/s/<username>`. Telegram отдаёт её
без логина, поэтому сервису не нужны ни api_id, ни телефон, ни сессия.

**Приватные каналы так не читаются.** У них нет публичной превью-страницы. Для них
нужна авторизация по QR — см. `sync.py` в истории проекта, но текущий сервис её
не использует.

Кэш в `feed.db` — SQLite, обновляется не чаще раза в 5 минут на канал, чтобы не
дёргать t.me на каждый перезапуск.

## Возможности

- **Два вида, а не модалка.** «Лента» и «Каталог» — равноправные разделы: каталог это
  основная задача, ему не нужны ни прерывание, ни защищённый фокус. Вид выбирается
  сегментом в шапке и запоминается.
- **Каталог** — открытый список TGMania, категории и поиск. Канал можно раскрыть,
  посмотреть последние публикации и отдельно добавить в свою ленту.
- **Свой канал** — добавление имени или ссылки `t.me/username` с проверкой доступности.
- **Личная лента** — посты только из выбранных каналов, вперемешку и по времени
  публикации. На странице показывается 80 записей; кнопка «Загрузить ещё» продолжает
  ту же хронологию. В ленте может быть до 200 каналов.
- **Непрочитанное** — отметки исключаются из следующих страниц, поэтому просмотренные
  посты не заполняют список «Только новые».
- **Поиск** — по постам в ленте и по названиям в каталоге, с задержкой ввода.
- **Вкладки каналов** — быстрый переход к одному каналу.
- **Медиа** — фото и видео. Видео грузится напрямую с CDN Telegram, сервер ничего не
  проксирует и не тратит трафик.
- **Профили** — вход по имени и паролю, отдельная лента для каждого человека.
  Для регистрации нужна почта: после перехода по ссылке из письма профиль активируется.
  Сброс пароля доступен по ссылке на подтверждённую почту. Первый профиль в браузере
  может перенести прежний список каналов.

## Токены

Цвета, тени и радиусы — переменные в `:root`. Контраст мелкого текста проверен
расчётом: минимум 4.5:1 (`--faint` 4.67:1 на карточке, `--dim` 6.85:1). Тени несут
смещение и размытие, чтобы читались как глубина, а не как ореол.

Иконки — инлайновый SVG-набор в начале документа, один штрих и вес. Символы юникода
(`👁`, `✕`, `✓`) как иконки не используются.

Оформление браузерных поверхностей — выделение текста, скроллбары, фокусные кольца —
тоже задано явно, иначе страница выглядит собранной из готовых блоков.

## Профили и хранение состояния

Подписки и прочитанные публикации хранятся в SQLite на сервере и привязаны к профилю.
Пароль хранится только в виде стойкого криптографического отпечатка. После входа браузер
получает закрытую сессию сроком на 30 дней. Имя профиля видно другим пользователям сайта;
оно не связано с аккаунтом Telegram.

Для сброса пароля используется подтверждённая почта. Её можно добавить или изменить в
настройках профиля после входа; новый адрес вступит в силу после подтверждения письмом.
Ссылки из писем ведут на `APP_BASE_URL` из `.env`: при публикации сайта укажи там его
публичный адрес с HTTPS. При регистрации в браузере, где уже была настроена лента,
прежние подписки и отметки прочитанного переносятся в новый профиль.

### Публикация для друзей

Регистрация открыта: каждый посетитель может создать собственный профиль. Для публикации
в интернете поставь сайт за прокси-сервер с HTTPS и включи для приложения переменную
`COOKIE_SECURE=1`. Без HTTPS пароли и сессии небезопасно передавать через интернет.
При локальном запуске по `http://127.0.0.1:8090` оставь значение `0`.

## Ограничения

- Только **публичные** каналы; приватные каналы через `t.me/s` не читаются.
- Превью `t.me` показывает около 20 последних постов на канал. Более глубокую
  историю получить нельзя; общая лента выдаётся страницами по 80 записей.
- Просроченные каналы обновляются параллельно, до 8 за раз. Если один источник
  недоступен, остальные продолжают показываться с предупреждением. Успешные ответы
  кэшируются на 5 минут.
- Сайт показывает только публичные каналы и их публичные публикации. Подписки и прочитанное
  разделены по профилям.

## Ежедневная работа

```bash
cd ~/Документы/Проекты/pet/telegram-lenta
docker compose up -d --build    # после изменений в коде
docker compose logs -f          # смотреть журнал
docker compose down             # остановить
```

Контейнер перезапускается сам (`restart: unless-stopped`), автозапуск при
загрузке macOS — через `docker compose` в LaunchDaemon или в Docker Desktop.

Логи запросов выключены, чтобы не засорять вывод. Включаются переменной:

```bash
LENTELE_LOG=1 docker compose up -d
```

### Проверка целостности интерфейса

```bash
.venv/bin/python check_ui.py
python3 -m unittest -v test_app.py
```

Сверяет, что все `id`, на которые ссылается скрипт, есть в разметке, что у
оверлеев есть `position:fixed`, и что нет внешних скриптов. Ловит именно тот
класс поломок, который не даёт ошибок в консоли: интерфейс просто молча
перестаёт работать.

## Файлы

| Файл | Назначение |
|---|---|
| `app.py` | Сервер: парсинг t.me, API `/api/feed` и `/api/check`, отдача UI |
| `index.html` | Интерфейс (без сборки и зависимостей) |
| `test_app.py` | Проверки порядка, страниц, частичных ошибок и синхронизации |
| `feed.db` | SQLite: посты, заголовки, профили, подписки, прочитанное |
| `sync.py`, `serve.py` | Вариант с авторизацией по QR — нужен для приватных каналов, сейчас не используется |
